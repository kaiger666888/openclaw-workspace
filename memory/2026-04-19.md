### glm-4.6v 空间位置估算能力（实测）
- 画面位置 (x%, y%)：±5-10%，可靠
- 深度排序（近/远）：可靠
- 绝对深度（米）：±1-3m，基于假设不精确
- 不能像 Depth Anything V2 输出像素级深度图

### blend 导入父子关系问题
- `bpy.data.libraries.load(link=False)` 丢失子对象父子关系
- `wm.append` 在 Blender 5.1 中 "nothing indicated" 错误（路径格式不对）
- 回退到 `libraries.load(link=False)`，但子对象仍然散落
- 根因：某些模型本身就没有父子关系（如 decorative_book_set_01 是 87 本散装书）
- potted_plant_01 子对象分散：pot 在 (0,0,0.3)，stem 在 (-2.7,-2.2,0.9)

### 场景渲染最佳成绩
- coffee_shop 模板：wide 5/8（沙发✅、电视✅、角色✅、地板✅、墙壁✅）
- 不可见元素原因：模型本身问题（散装书太小、盆栽子对象分散），不是相机问题
- 相机固定位置有效：`lens=18mm pos=(-1.0,-3.0,2.5) look=(0.5,0.5,0.5)`

### TripoSR 图片→3D 验证（新功能）
- kais-blender-engine 更新，新增 TripoSR 本地推理 + Tripo API
- API：`POST /generate/image23d`（TripoSR 本地）、`POST /generate/text23d`（Tripo API）
- **TripoSR 已在 Windows 端可用**（torch 已安装），Tripo API 不可用（没配 key）
- **完整管线验证通过**：Blender 渲染猴子 → TripoSR 图片→3D(.glb) → 导入 Blender → 渲染
- 生成模型质量一般：无纹理，几何体简单，体积小（0.27×0.03×0.57m）
- 注意：`POST /generate/import/{job_id}` 是独立 Blender 进程，模型不持久化到主场景
- 正确导入方式：在已有场景脚本中用 `bpy.ops.import_scene.gltf(filepath=...)`
- 没有 upload API，image_path 必须是 Windows 端本地路径
- glb 导入用 `bpy.ops.import_scene.gltf`，不是 `wm.append` 或 `wm.link`

### Blender 5.1 API 变化
- `import_scene` 不是直接可调用的，必须用 `bpy.ops.import_scene.gltf(filepath=...)`
- `wm.append` 路径格式要求 `filepath + '\\Object'`，单独 filepath 会报 "nothing indicated"
- `view_layer.update()` 必须在取 AABB 前调用
