### P0 执行过程
1. **并行审计** — Router 代码审查（修复5个bug）+ Hermes MCP 桥接验证（全部通过）
2. **Docker 构建** — telegram-router 镜像构建成功（204MB）
3. **发现架构冲突** — OpenClaw Telegram 插件用 long-polling，Router 假设 webhook，导致 bot token 冲突
4. **方案A决策** — 取消外部 Router，改内嵌路由模式（SOUL.md 规则 + MCP 调用）
5. **MCP 连接问题** — mcp.servers 仅供 acpx runtime adapters 使用，主 agent 不能直接调用 stdio MCP server
6. **mcporter 桥接方案** — 通过 mcporter call 桥接，4个认知工具全部验证通过

### 关键决策
- 方案A内嵌路由 > 方案B webhook 模式（最小侵入，无部署复杂度）
- mcporter 桥接 > acpx 路径 > HTTP 改造（零改造，利用现有基础设施）

### 技术发现
- OpenClaw mcp.servers 是受保护配置路径，不能通过 config.patch 写入 command/args/env
- 需要直接编辑 openclaw.json 或使用 openclaw mcp set 命令
- Gateway 的 /api/status 端点在重启期间不稳定
- mcporter 已支持 session 复用机制
